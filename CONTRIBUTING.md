# Contributing

Start with the [development guide](docs/development.md). Small contributions are easier to verify: reproduce one invalid state transition, add a regression test, or document a startup failure.

Include the expected behavior, actual behavior, relevant command and synthetic input. Keep production credentials, real account details and private stories out of issues and fixtures. Discuss changes to storage contracts or world snapshots before implementing a broad migration.

For a pull request, explain the observable change and run the checks for the affected packages. State explicitly when middleware or live-model tests were skipped. Avoid unrelated formatting or generated files.

Please only submit code and assets you have permission to redistribute. AI-assisted contributions should receive the same factual review and testing as any other contribution.
